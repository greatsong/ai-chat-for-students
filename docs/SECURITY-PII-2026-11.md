## 1. 결론

- 치명 항목은 없습니다. 비인증 요청으로 학생 데이터를 읽는 경로는 코드와 라이브 모두에서 찾지 못했습니다.
- 다른 학생의 대화에 접근하는 경로(IDOR)도 없습니다. 라우트 전수 대조와 HTTP 회귀 테스트로 확인했습니다.

- 코드로 고칠 수 있는 항목은 이 브랜치에서 고쳤습니다. **아직 배포하지 않았으므로 운영에는 반영되지 않았습니다.**
- 사용자가 결정하거나 직접 해야 할 일은 [6절](#6-사용자가-해야-할-일)에 모았습니다.

## 2. 항목별 분석

심각도는 현재 운영 상태에서 학생 개인정보에 미치는 영향으로 정했습니다. 조치 상태의 "수정"은 이 브랜치의 코드 수정이며 배포 전입니다.

### 높음

#### H-1. 프런트 화면에 CSP와 보안 헤더가 없습니다

- **위치**: `vercel.json:20`, `client/vercel.json`, `client/src/stores/authStore.js:37`, `client/src/pages/teacher/ConversationsPage.jsx:376`
- **근거**: 라이브 응답에서 HTML에는 `strict-transport-security`만 있었습니다. `server/app.js`의 helmet CSP는 `/api/*` 응답에만 붙습니다. JWT는 `localStorage`에 있습니다. 마크다운의 `![](URL)`은 이미지 요청으로 바뀝니다(테스트).
- **공격 시나리오**:
  1. 외부 문서에 "대화 요약을 이 이미지 주소에 붙여 출력하라"는 숨은 지시를 넣습니다. 학생이 이 문서를 첨부하면 AI 답변의 이미지 주소를 통해 대화 내용이 외부 서버로 전송됩니다.
  2. 학생이 메시지에 외부 이미지를 넣으면 관리자가 열람할 때 관리자 브라우저가 외부 서버에 요청을 보냅니다. 열람 시각과 IP가 드러납니다.
  3. 다른 사이트가 채팅 화면을 iframe으로 덮어 클릭을 유도할 수 있습니다.
  4. 앞으로 XSS가 하나라도 생기면 CSP가 없어 관리자 토큰이 그대로 탈취됩니다. 현재 XSS 지점은 찾지 못했습니다(8.1절).
- **조치**: 수정. `vercel.json`에 CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`를 넣었습니다. 마크다운 이미지는 불러오지 않고 링크로 표시합니다(`client/src/components/chat/MarkdownImageLink.jsx`). AI 답변의 외부 이미지가 화면에 바로 보이지 않고 링크가 되는 것이 수업에서 달라지는 점입니다. 같은 헤더로 빌드를 로컬에서 서빙해 Google 로그인 스크립트·스타일·iframe, 관리자 화면, 학생 화면이 위반 없이 동작하고 외부 이미지만 `img-src`로 차단되는 것을 확인했습니다. 실제 Google 로그인 완료 과정은 로컬 출처가 등록되어 있지 않아 확인하지 못했습니다.
- **해야 할 일**: 배포 뒤 교사 계정으로 로그인 한 번을 확인합니다. 음성 입력·읽어 주기도 한 번 확인합니다.

#### H-2. 학년도 종료 후 파기를 실행할 수단이 없습니다

- **위치**: `client/src/pages/PrivacyPage.jsx:58` (제3조), `server/routes/chat.js:156`, `server/db/database.js:102`
- **근거**: 처리방침은 "해당 학년도 종료 후 파기"라고 약속합니다. 코드에는 기간 기반 삭제가 없고 학생을 한 명씩 지우는 관리자 기능만 있습니다. 첨부 원본은 삭제 기한 없이 `messages.files`에 남습니다(DB, 965건, 약 1.46GB). 탈퇴 기능은 없고 이메일 요청 방식입니다.
- **공격 시나리오**: DB 토큰이나 관리자 계정이 유출되면 누적된 전체 대화와 첨부 원본이 한 번에 노출됩니다. 기간이 길수록 피해가 커집니다. 파기를 하지 않으면 처리방침 위반이 됩니다. 2026-11-05 기준 자료는 모두 2026학년도라 아직 위반은 아닙니다(DB).
- **조치**: 일부 수정. `server/scripts/purge-school-year.mjs`와 `server/utils/retention.js`를 추가했습니다. 기본은 건수만 출력하고 `--execute`를 붙여야 지웁니다. 지금 학생이면서 학생일 때 만든 대화만 대상으로 하며 한 트랜잭션으로 처리합니다. 기준은 메시지 작성일입니다. 새 학년도에 이어 쓴 대화는 이전 메시지만 지우고 제목을 바꿉니다. 임시 DB에서 검증했고 운영에서는 실행하지 않았습니다.
- **해야 할 일**: 2027학년도 시작 전 실행 일정을 정합니다. 첨부 원본을 일정 기간 뒤 지울지 결정합니다(6절).

#### H-4. 로그아웃 뒤 같은 탭에 이전 사용자의 대화가 남습니다

- **위치**: `client/src/stores/authStore.js:90`, `client/src/stores/chatStore.js:7`, `client/src/pages/ChatPage.jsx:136`
- **근거**: 로그아웃은 인증 상태만 지우고 `chatStore`의 `messages`, `currentConversation`은 그대로 두었습니다. 화면 이동도 새로고침 없는 라우터 이동이었습니다(코드, 코덱스 검토에서 발견).
- **공격 시나리오**: 컴퓨터실에서 학생 A가 대화를 연 채 로그아웃하고 학생 B가 같은 탭에서 로그인하면 A의 대화와 첨부 내용이 B의 화면에 보입니다. 기록 내보내기도 가능합니다.
- **조치**: 수정. 로그아웃하면 `/login`으로 전체 새로고침해 현재 탭의 메모리 상태를 비웁니다. 로그아웃 요청은 유지되며, 이미 시작된 서버 처리의 취소는 보장하지 않습니다. 브라우저 실행 확인은 하지 않았고 코드로 확인했습니다.
- **해야 할 일**: 배포 뒤 공용 PC에서 로그아웃과 다른 계정 로그인을 한 번 확인합니다.

### 중간

#### M-1. 공유한 대화를 지우면 메시지만 지워지고 실패합니다

- **위치**: 수정 전 `server/routes/conversations.js:157`, `server/routes/teacher.js:738`. 수정 후 `server/routes/conversations.js:156`, `server/routes/teacher.js:775`, `server/db/database.js:681`
- **근거**: 운영 DB는 외래 키를 강제합니다(DB). `share_tokens`가 대화를 참조하는데 삭제 경로가 토큰을 지우지 않습니다. 재현 결과 메시지는 지워지고 대화 삭제가 `SQLITE_CONSTRAINT`로 실패해 500이 났습니다(테스트).
- **시나리오**: 학생이 삭제를 요청해도 대화 행과 제목(첫 메시지 앞 50자)이 남습니다. 학생은 실패 화면을 보고 내용은 사라집니다. 운영에서 이 상태가 된 대화는 0건입니다(DB).
- **조치**: 수정. 공유 토큰, 메시지, 대화를 한 트랜잭션으로 지웁니다.
- **해야 할 일**: 없습니다.

#### M-2. 7일 토큰을 폐기할 수단이 없고 공용 PC에 남습니다

- **위치**: `server/routes/auth.js:155`, `client/src/stores/authStore.js:37`
- **근거**: 토큰은 7일 유효하고 `localStorage`에 있습니다. 로그아웃은 브라우저에서 지우기만 했습니다. 서버 폐기 수단이 없어 유일한 비상 수단이 `JWT_SECRET` 교체였습니다.
- **공격 시나리오**: 컴퓨터실에서 로그아웃하지 않고 자리를 뜨면 다음 사람이 7일 안에 그 학생의 대화를 읽습니다. 복사된 토큰은 로그아웃 뒤에도 유효했습니다.
- **조치**: 일부 수정. `users.token_version`을 추가해 로그아웃(`server/routes/auth.js:203`)과 교사 해제 때 이전 토큰을 즉시 무효화합니다(`server/middleware/auth.js:79`). 기존 토큰은 `tv`가 없어 0으로 처리되므로 배포해도 아무도 로그아웃되지 않습니다. 로그아웃하면 그 사용자의 다른 기기도 함께 로그아웃됩니다. 로그아웃은 로그인 한도(IP당 분당 100회)에서 제외했습니다(`server/app.js`). 전역 한도(IP당 분당 3,000회)가 소진되거나 네트워크가 끊겨 요청이 실패하면 브라우저 토큰만 지워지고 서버 폐기는 되지 않습니다.
- **해야 할 일**: 학생 토큰 유효기간을 줄일지 결정합니다(6절). 코드는 그대로 7일입니다.

#### M-3. Google 토큰 검증이 일부 조건에서 느슨합니다

- **위치**: 수정 전 `server/routes/auth.js:47`, `:63`. 수정 후 `server/routes/auth.js:49`, `:65`, `server/utils/googleIdentity.js`
- **근거**: `GOOGLE_CLIENT_ID`가 없으면 `aud` 검사를 건너뛰었습니다. 운영에는 설정되어 있습니다(Railway 변수 이름 확인). `email_verified`와 `hd`는 보지 않았습니다. `danggok.hs.kr` MX는 Google이므로 학교 계정은 Workspace입니다(라이브 DNS).
- **공격 시나리오**: 교사·관리자 명단의 외부 메일이 Gmail이 아닌 경우, 그 주소로 이메일 미검증 Google 계정을 만들어 교사 권한을 얻을 수 있습니다. 명단의 실제 주소는 출력하지 않아 해당 여부는 미확인입니다. 설정 누락 시 다른 앱에서 받은 ID 토큰을 재사용할 수 있습니다.
- **조치**: 수정. `GOOGLE_CLIENT_ID`가 없으면 거부하고, `email_verified`를 요구하며, 학교 메일은 `hd`도 확인합니다.
- **해야 할 일**: 배포 뒤 학생 계정 로그인 한 번을 확인합니다. Workspace 밖의 학교 메일 계정이 있다면 로그인이 막힙니다.

#### M-4. 관리자의 학생 대화 열람이 기록되지 않았습니다

## 4. 분석 항목별 결과

### 4.1 교사·관리자 권한

- 역할은 JWT 값이 아니라 DB `users.role`로 판정합니다(`server/middleware/auth.js`, 테스트로 고정).
- 로그인 때 역할은 `ADMIN_EMAILS`, `TEACHER_EMAILS`, `teacher_emails` 설정으로 다시 계산합니다(`server/routes/auth.js`). 학생이 스스로 역할을 바꾸는 경로는 없습니다. `PATCH /students/:id` 스키마에 `role`이 없고 설정 허용 목록에 `teacher_emails`가 없습니다.
- **교사는 학생 대화를 볼 수 없습니다.** 대화 열람 라우트가 모두 `requireAdmin`입니다. 문서의 "교사가 모니터링한다"는 실제로 관리자 1명입니다. 따라서 "자기 수업 밖 학생을 보는" 문제는 없고, 대신 관리자 계정 하나가 학생 대화 1,170건 전체를 봅니다. `classroom_id`는 범위 제한에 사용되지 않습니다.
- `premium_models`는 모델 사용 예외일 뿐 다른 권한을 주지 않습니다(`server/utils/modelAccess.js`). 관리자만 바꿀 수 있고 운영에서 0명입니다.
- 5분 인증 캐시: HTTP 변경 경로는 `invalidateUserCache()`를 호출하고, 복제본이 1개입니다(Railway 배포 정보). 복제본을 늘리거나 파기 도구로 계정을 지우면 실행 중 서버에 최대 5분 늦게 반영됩니다.

### 4.2 인증

- Google 로그인은 ID 토큰을 tokeninfo로 검증합니다. 팝업 credential 방식이라 OAuth `state`를 사용하지 않습니다. `nonce`도 없어 탈취된 ID 토큰은 만료 전까지 재사용될 수 있습니다.
- JWT 비밀값은 64자입니다(길이만 확인). 저장 위치는 `localStorage`, 만료는 7일입니다.
- 쿠키를 사용하지 않고 `Authorization` 헤더만 사용하므로 CSRF 대상이 아닙니다.
- 위조 토큰: Vercel 경유 요청은 Vercel 방화벽이 403으로 막았고, Railway 직접 요청은 서버가 401로 거부했습니다(라이브).

### 4.3 저장 데이터

- 대화 본문, 첨부 원본, 생성 이미지는 Turso에 평문으로 저장됩니다. 저장 시 암호화는 앱 수준에서 하지 않습니다. Turso 측 암호화와 백업 보관 기간은 미확인입니다.
- 업로드 파일은 임시로 디스크에 쓰고 응답 전에 삭제를 시도합니다. 실패한 파일은 서버 시작 때 24시간 기준으로 정리합니다. 공개 URL이 없습니다(`server/routes/upload.js`).
- 삭제 기능은 하드 삭제입니다. 백업에 남는 기간은 미확인입니다.
- Turso는 무료 starter 요금제이며 1.5GB/5GB를 사용합니다(2026-10-16 기록). 학생 데이터를 무료 요금제에 두는 것이 학교 규정에 맞는지는 사용자 확인 사항입니다.

### 4.4 공유 파이프라인

코드 확인 결과 설계대로 동작합니다.

- 토큰: 256비트 난수, SHA-256 해시만 저장, 기본 10분 만료(`SHARE_TOKEN_TTL_MINUTES`로 변경 가능), 원자적 일회용 소비. 없음·사용됨·만료가 같은 404입니다.
- 전달 범위: 대화 제목, 제공사, 표시 이름, 턴의 역할·본문·시각, 첨부 파일명입니다. 첨부 원본 필드와 생성 이미지 URL 필드는 제외합니다. 본문에 포함된 마크다운 이미지 주소 등은 그대로 전달합니다.
- 평가 앱 쪽: 해시에서 토큰을 읽은 뒤 `history.replaceState`로 지웁니다. 그 뒤 처리는 원래 세션의 평가 앱 점검 범위입니다.
- CORS: 평가 앱 출처는 허용, 다른 출처는 허용 헤더 없음(라이브 OPTIONS로 확인). Vercel 프록시가 `Origin`과 응답 CORS 헤더를 전달합니다(라이브).
- 전역 CORS 제외의 영향: 토큰 발급 `POST /api/share`에는 CORS 헤더가 없지만 같은 출처 호출이라 정상입니다. 인증은 Bearer입니다.
- 남은 판단: 표시 이름에 학번이 들어가 평가 앱으로 전달됩니다. 평가 화면 표시에 사용하므로 유지했고 처리방침에 적어야 합니다.

### 4.6 프롬프트 주입

- AI에게 DB나 다른 사용자 데이터에 닿는 도구가 없습니다. 코드 실행은 제공사 샌드박스에서 돌고 서버 내부 자료를 받지 않습니다.
- 대화 이력은 그 대화의 메시지만 전달합니다.
- 따라서 프롬프트 주입으로 다른 학생 데이터를 읽는 경로는 없습니다. 자기 대화가 외부로 나가는 경로는 H-1의 이미지 주소입니다. 자동 요청은 링크 표시와 CSP로 막습니다. 주소에 내용이 실린 링크를 사용자가 직접 누르면 전송될 수 있습니다.

### 4.7 로그·오류

- 정상 처리 로그에 대화 본문을 출력하는 코드는 없습니다. 사용자·대화 id, 교사 이메일(감사 로그), 비프로덕션의 첨부 파일명은 기록합니다.

### 4.8 웹 공격면

## 6. 사용자가 해야 할 일

### 배포 전 결정

1. **이 브랜치 배포 승인.** 순서는 서버(`railway up`) 다음 프런트(`vercel --prod --force`)입니다. 서버가 기동할 때 `users.token_version` 컬럼을 자동 추가합니다.

4. **Railway에 `NODE_ENV=production` 명시.**
